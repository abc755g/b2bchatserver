# Changelog

## [v1.5.0] — 06.10.2026

Вход через B2B-портал попадает в существующий аккаунт сотрудника и не создаёт
новых; Client ID сервер берёт у портала сам.

**При обновлении:** нужен портал v1.0.124 или новее. Если вход через портал
разрешён, после подтверждения домена в портале выполните
`./manage.sh portal-login`. Строку `INSTALL_PORTAL_LINK_LOCALPART` из `.env`
команда уберёт сама.

### Изменено
- **Вход через B2B-портал попадает в существующий аккаунт и не создаёт новых.**
  Портал (v1.0.124+) присылает в scope `b2b_matrix` логин сотрудника на сервере
  компании — только подтверждённый входом на этот сервер, — и без такого
  подтверждения сам не пускает. MAS берёт логин из `b2b_mxids["<server_name>"]`
  и связывает вход с аккаунтом сам (`on_conflict: set`). Ручное связывание
  («сначала паролем, потом через портал») и флаг `--link-by-localpart` убраны.
- **`./manage.sh portal-login` без аргументов** — Client ID берётся у портала
  по `server_name`; копировать его с экрана не нужно. `--client-id` остаётся
  для ручной подстановки. Установщик забирает ID сам, если домен уже
  подтверждён, а `verify-domain` напоминает о `portal-login`.

## [v1.4.1] — 06.10.2026

Установщик больше не выбирает ответы за пользователя при запуске через
`curl … | bash`.

**При обновлении:** ничего делать не нужно — меняется только `install.sh`,
который скачивается при каждом запуске.

### Исправлено
- **`curl … | bash` молча выбирал ответы за пользователя.** Девять вопросов
  `install.sh` (режим «изменить/переустановить», режим установки, клиенты,
  бэкапы, регистрация, SMTP) читали стандартный ввод, а при запуске через
  конвейер это сам скрипт: вопрос получал следующую строку кода, и на рабочем
  сервере расширенный режим тихо сменился рекомендуемым. Теперь все вопросы
  читают терминал.

## [v1.4.0] — 06.10.2026

Вход на сервер компании через B2B-портал — дополнительным поставщиком в MAS,
рядом с паролем и IdP компании.

**При обновлении:** при включённом MAS `install.sh` впервые спросит «Разрешить
вход через B2B-портал?» с ответом «да» по умолчанию. Это только согласие: сам
вход включается `./manage.sh portal-login --client-id <ID>`, когда портал
подтвердит домен и выдаст ID. Существующих сотрудников предупредите, что при
первом входе через портал аккаунт нужно связать (сначала вход паролем).

### Добавлено
- **Вход через B2B-портал.** `install.sh` при включённом MAS спрашивает
  «Разрешить вход через B2B-портал?» (по умолчанию «да», в том числе в
  рекомендуемом режиме и на серверах, где вопроса ещё не было) и передаёт
  выбор в `start.sh` флагом `--portal-login`; в `.env` — `INSTALL_PORTAL_LOGIN`.
  Портал становится **дополнительным** поставщиком входа в MAS рядом с паролем
  и IdP компании, а не заменой: при его недоступности пропадает только кнопка.
  Client ID портал выдаёт после подтверждения домена, подключение —
  `./manage.sh portal-login --client-id <ID>`. У провайдера портала
  фиксированный id, поэтому `redirect_uri` портал вычисляет сам. Существующий
  аккаунт к порталу сам не привязывается: сотрудник входит паролем, затем через
  портал в том же браузере, и MAS предлагает связать. Сопоставление по логину
  без пароля — только явно, `--link-by-localpart`. Подробно и о том, что
  обсудить с компанией до включения, — в `docs/external-integration.md`.

### Исправлено
- **`manage.sh oidc` закрывал открытую регистрацию.** Признак брался из
  `enable_registration` в `homeserver.yaml`, который при MAS всегда выключен, и
  каждое подключение провайдера записывало в MAS
  `password_registration_enabled: false`. Теперь значение читается из конфига
  MAS. Там же: строки `INSTALL_OIDC_*`, которых нет в `.env` старых установок,
  не сохранялись, а повторная настройка MAS добавляла по пустой строке перед
  `matrix:`.
- **`manage.sh mas register-user` без терминала навсегда занимал ядро.** Без
  `--yes` mas-cli открывает интерактивное меню, а на закрытом stdin оно
  крутится на 100% CPU и не завершается. Клиент `docker` при этом мог
  отвалиться, а процесс внутри контейнера MAS оставался: на рабочем сервере
  такой висел двое суток. README утверждал, что в этом режиме вопросы просто
  пропускаются, — это неверно. Теперь `manage.sh` без терминала отклоняет
  `register-user` без `--yes` и подсказывает, как задать пароль флагом.

## [v1.3.3] — 01.10.2026

Не работали «Управление аккаунтом», сброс идентификации и восстановление
пароля; nginx падал без любого из сервисов; повторный запуск не применял
конфиги. Добавлена политика шифрования переписки.

**При обновлении:** режим шифрования по умолчанию — `backup`. После обновления
Element попросит каждого сотрудника создать ключ восстановления и не даст
работать без него — предупредите сотрудников заранее или выберите `off`.

### Добавлено
- **Политика шифрования переписки.** `install.sh` спрашивает, шифровать ли
  переписку, и передаёт выбор в `start.sh` флагом `--e2ee backup|off`; выбор
  сохраняется в `.env` как `INSTALL_E2EE`. Раньше шифрование включалось
  клиентом по умолчанию, а ключ восстановления создавать не требовалось: сотрудник,
  сменивший ноутбук, безвозвратно терял зашифрованную историю. В режиме
  `backup` (по умолчанию) Element не даёт работать без ключа восстановления
  (`secure_backup_required` в `/.well-known/matrix/client`) и требует
  подтверждать новые устройства (`force_verification`). В режиме `off` новые
  комнаты создаются без шифрования.

### Исправлено
- **«Управление аккаунтом» открывалось пустым, а сброс идентификации не
  проходил.** Страница аккаунта MAS берёт все данные через `/graphql`, а nginx
  отправлял этот путь в Element и получал 404. Сброс кросс-подписи упирался в то
  же самое: подтвердить его в MAS было нечем, и клиент раз за разом получал 401
  на `keys/device_signing/upload`. Восстановление пароля не работало по той же
  причине: в списке путей MAS стоял `recovery`, а MAS обслуживает `/recover`.
  Заодно к MAS направлены `/.well-known/webfinger` и
  `/.well-known/change-password` — раньше они уходили в статическую папку.
- **nginx не запускался, пока не поднят любой из сервисов.** Адреса контейнеров
  резолвились один раз при старте: если element, mas, livekit или другой
  upstream ещё не был готов, nginx падал с `host not found in upstream` и сайт
  лежал целиком. По той же причине после пересоздания одного контейнера nginx
  слал запросы на его старый IP и отдавал 502 до собственного перезапуска.
  Теперь адреса резолвятся через DNS Docker на каждый запрос: недоступный
  сервис даёт 502 только на своих путях.
- **Повторный запуск не применял новые конфиги.** `docker compose up -d`
  пересоздаёт только контейнеры с изменившимся описанием в compose, а
  `homeserver.yaml`, конфиг nginx, MAS, LiveKit и Element смонтированы с диска:
  после «изменить настройки» файлы обновлялись, а сервисы работали со старыми,
  пока их не перезапустить руками. Element к тому же копирует свой конфиг один
  раз при старте. Теперь в режиме изменения настроек эти сервисы
  перезапускаются.
- **Ложное «Войти под администратором не удалось» при повторном запуске.**
  Без смены пароля проверке нечем войти, но она считала это сбоем и
  объявляла сервер нерабочим. Теперь в этом случае вход не проверяется.

## [v1.3.2] — 30.09.2026

Релиз исправлений: не работали загрузка файлов и звонки, а сбои установки
проходили молча.

### Исправлено
- **Загрузка файлов падала с 500 на любой установке.** Том `synapse_media`
  Docker создаёт сам — пустым, от root и с правами 755, а Synapse в образе
  работает под uid 991: первый же файл получал
  `PermissionError: [Errno 13] Permission denied: /data/media_store`. Правка прав
  в `start.sh` существовала, но выполнялась под тем же uid 991, который чужой
  каталог перехватить не может, а `|| true` прятал провал. Теперь каталог
  создаётся с нужным владельцем прямо в образе (свежий том Docker засевает из
  образа вместе с правами), а для уже существующих установок `chown` идёт от
  root и сообщает об ошибке вместо молчания.
- **Звонки не соединялись при `--bind-ip`.** Порты 50000-50010 публиковались на
  указанном адресе, а LiveKit определял свой адрес сам, по исходящему трафику —
  то есть основной IP сервера. Клиент получал ICE-кандидата на адрес, где эти
  порты не открыты: сигнальный канал жив, участник входит в комнату, звонок
  «идёт», и молча нет ни звука, ни картинки. Теперь при заданном `--bind-ip` в
  `livekit.yaml` пишется `node_ip` с тем же адресом.
- **Логин администратора не проверялся.** Установщик принимал почтовый адрес,
  создание пользователя в MAS падало, а на экран всё равно печаталось «Что
  делать дальше». Логин проверяется при вводе: Matrix-адрес устроен как
  `@логин:домен`, поэтому «@», двоеточия и заглавные буквы недопустимы.
- **Провал создания администратора был предупреждением, а не ошибкой** —
  установка досчитывала до экрана успеха без администратора. Теперь
  останавливается.
- **Существование пользователя в MAS определялось по режиму установки.**
  `INSTALL_MODE` становится `modify` как только есть `.env`, а он остаётся и
  после прерванной установки, когда аккаунта ещё нет: скрипт уходил менять
  пароль несуществующему пользователю. Теперь проверяется делом.
- **Подсказки времён до MAS.** Admin UI работает с Synapse, а при включённом MAS
  учётные данные живут в MAS: созданный через панель аккаунт остаётся без пароля
  в MAS, и войти в него нельзя. Советы «создавайте аккаунты в Admin UI» и
  «смените пароль через Admin UI → Users» убраны из README и `password-reset`.
- **`manage.sh mas` терял интерактивный запрос пароля.** `mas_cli` ходит с `-T`
  (это нужно там, где вывод забирается в переменную), но `register-user` без
  терминала молча пропускает вопросы и создаёт аккаунт, в который нельзя войти.
  Прокладка `mas` теперь пробрасывает терминал, когда команду набирает человек.

### Добавлено
- Итоговая самопроверка установки: отвечает ли Matrix API, доступно ли хранилище
  медиа на запись, удался ли вход администратора и — если домен пользователей
  отличается от домена сервера — работает ли делегация well-known. Каждая из
  починенных выше поломок раньше всплывала только когда пользователь не мог
  войти, отправить файл или позвонить.
- Предложение сохранить ключ подписи сразу после установки, с объяснением, что
  именно сломается при его потере, и готовыми командами, чтобы унести файл с
  сервера и не оставить копию.
- Раздел README про регистрацию по токенам: пароль задаёт сам сотрудник, и
  администратор его не видит — в отличие от `register-user`, где пароль проходит
  через терминал, историю оболочки и переписку.
- `admin-token` предупреждает, что печатает токен с правами администратора
  открытым текстом, и подсказывает `kill-sessions`: сессии не истекают сами, а
  каждый вызов создаёт новую.
- `.dockerignore`: секреты и данные не попадают в контекст сборки.

### Изменено
- Выбранный режим установки запоминается сразу после ответа, а не после
  успешного прогона — при падении в середине повтор снова предлагал
  «рекомендуемые», хотя повтор и есть тот случай, когда выбор важно сохранить.
- `__pycache__` больше не хранится в репозитории и не попадает в архив релиза.

## [v1.3.1] — 23.09.2026

Релиз исправлений: v1.2.0 и v1.3.0 не устанавливались с нуля.

### Исправлено
- **`lib/` не попадал в архив релиза.** `start.sh` и `manage.sh` вызывают
  `python3 lib/mas-config.py`, а `tar` в `release.yml` собирал только
  `start.sh manage.sh config/`. Любая установка с MAS падала на настройке
  аутентификации, а MAS включён по умолчанию — то есть установить v1.2.0 или
  v1.3.0 с нуля было нельзя. Каталог добавлен в архив и в проверку обязательных
  файлов в CI; `install.sh` копирует его и в ветке локальных файлов; `start.sh`
  теперь сообщает о пропаже понятной ошибкой вместо трейсбека Python.
- **Образ MinIO не скачивался.** Репозиторий `minio/minio` на Docker Hub отдаёт
  404 и `pull access denied`. Официальные образы остались на `quay.io`, тег тот
  же — `IMG_MINIO` переведён туда.
- **Проверка A-записи ругалась на верную настройку.** Домен сверялся только с
  адресом, с которого сервер ходит наружу. На сервере с несколькими IP чат
  может жить на любом из них, и установщик требовал подтвердить «некорректную»
  A-запись. Теперь совпадение с любым адресом сервера считается корректным, а
  найденный адрес предлагается по умолчанию при выборе привязки портов.
- **Режим «рекомендуемые параметры» отменял прежние настройки.** При повторном
  запуске на работающем сервере он молча выключал MinIO (уже загруженные медиа
  стали бы недоступны), сбрасывал звонки и режим регистрации к умолчаниям и
  снимал установленные Cinny и FluffyChat. Все эти значения теперь читаются из
  `.env`.
- **Список адресов сервера содержал мосты Docker** (`docker0`, `br-*`) — у них
  тоже `scope global`. Публиковать на них порты бессмысленно, из выбора убраны.
- **Привязка портов предлагалась неверно.** При нескольких адресах по умолчанию
  подставлялся первый в списке, и Enter уводил сервис не на тот адрес. Теперь
  подставляется адрес из A-записи домена, а если определить его нельзя —
  установщик требует ввести адрес явно. Сам вопрос при нескольких адресах
  по умолчанию отвечает «да».
- **Настроенный SMTP ничего не отправлял.** В `homeserver.yaml` не попадал
  `enable_notifs`, а у Synapse он по умолчанию `false`: блок `email` лежал в
  конфиге мёртвым грузом. Письма о пропущенных сообщениях и приглашениях
  включены.

### Изменено
- Выбранный режим установки запоминается в `.env` (`INSTALL_ADVANCED_SETUP`) и
  подставляется при следующем запуске — раньше расширенная настройка каждый раз
  сбрасывалась на «рекомендуемые».
- MinIO предлагается включённым по умолчанию.
- Каталог локальных бэкапов по умолчанию: `/opt/backups/matrix` → `/srv/backups/matrix`.

## [v1.3.0] — 23.09.2026

Тема релиза: установка на сервер, где уже что-то работает.

### Добавлено
- **`--bind-ip`** у `start.sh` — публиковать порты чата только на указанном
  адресе. Без флага Docker занимает 80 и 443 на всех интерфейсах, и на сервере
  с другим сайтом контейнер nginx падает с `port is already allocated`. Префикс
  получают все публикации: nginx (80, `--port`, 8448, Admin UI), динамические
  порты Cinny, FluffyChat и MinIO, а также LiveKit (7880, 7881 и UDP-диапазон
  50000–50010). IPv6 оборачивается в скобки. Coturn флаг не затрагивает — он
  работает с `network_mode: host`.
- `install.sh` спрашивает про привязку, когда это нужно: в расширенной настройке,
  при нескольких глобальных адресах сервера или когда 80-й порт уже занят на всех
  интерфейсах. Адрес сохраняется в `.env` как `INSTALL_BIND_IP`, повторные
  запуски его не теряют.
- Раздел README «Если на сервере уже есть другой сайт».

### Изменено
- **Ломающее: каталог установки по умолчанию `/opt/b2b-chat` → `/srv/b2b-chat`.**
  Свежая установка встанет по новому пути. У тех, кто уже поставил сервис в
  `/opt/b2b-chat`, обновлённый `manage.sh` будет искать его в `/srv` и сообщит,
  что установка не найдена, а повторный `install.sh` развернёт вторую копию.
  Варианты: перенести каталог (`mv /opt/b2b-chat /srv/b2b-chat` при остановленном
  стеке, затем `docker compose up -d` из нового пути — bind-mount'ы прописаны
  абсолютными путями, поэтому контейнеры нужно пересоздать) либо оставить старый
  путь и подставить симлинк `ln -s /opt/b2b-chat /srv/b2b-chat`.
- Проверка DNS при заданном `--bind-ip` сверяет A-запись с этим адресом, а не с
  тем, что вернёт `api.ipify.org`. На сервере с несколькими адресами наружу
  трафик может идти с другого интерфейса, и проверка ложно ругалась на верный DNS.

## [v1.2.0] — 18.09.2026

Тема релиза: федерация с партнёрскими серверами и подключение к внешним сервисам.

### Добавлено
- **MAS** (matrix-authentication-service `1.23.0`) в стек: опция `--mas`, для новых
  установок включена по умолчанию. База MAS создаётся в том же Postgres, конфиг
  генерирует сам MAS и правит `lib/mas-config.py`. С MAS работают Element X и
  вход через внешних OIDC-провайдеров; регистрация и пароли на стороне Synapse
  при этом выключаются.
- `manage.sh federation` без меню: `--list`, `--add`, `--remove`, `--mode`,
  `--sync-from <url>` (JSON-массив, `{"domains":[...]}` или построчно) и
  `--test <domain>` — проверка well-known, ключей сервера и собственной видимости.
- `manage.sh verify-domain --token [--path NAME]` — публикует токен подтверждения
  владения доменом по `/.well-known/NAME`. По умолчанию `b2b-matrix-verify` — путь,
  который проверяет B2B-портал; другому сервису имя задаётся через `--path`. Для
  этого well-known отдаётся файлами из `config/nginx/well-known/`, а не `return 200`
  в конфиге nginx.
- `manage.sh backup-key` — выгрузка ключа подписи отдельно от общего бэкапа;
  `start.sh` напоминает об этом сразу после установки.
- `manage.sh oidc --issuer --client-id [--name]` / `--disable` — внешний
  OIDC-провайдер для MAS; `manage.sh mas <...>` — прокладка к `mas-cli manage`;
  `manage.sh mas-migrate [--apply]` — `syn2mas` для существующих аккаунтов;
  `manage.sh admin-token` — токен для Admin UI (через MAS или паролем).
- Листенер федерации на `:8448` в nginx и compose — порт был открыт в ufw,
  но ничего на нём не слушало; работала только делегация через well-known.
- `.well-known/matrix/client` с MAS содержит `org.matrix.msc2965.authentication`,
  без этого Element X не находит, куда логиниться.
- Образ Synapse собирается всегда и включает `synapse-http-antispam==0.5.1` —
  модуль, который отдаёт решения о приглашениях, входе в комнаты и видимости в
  поиске внешнему HTTP-сервису. Без блока `modules:` в `homeserver.yaml` он
  ничего не делает; как включить — в `docs/external-integration.md`.
- Блок «Федерация» в `install.sh` отдельно предлагает сервер B2B-портала
  `chat.b2b-links.ru` (по умолчанию «да»; при перенастройке — как было раньше).
  Инсталлятор знает адреса портала, но ничего не подключает без согласия.
- Политика регистрации OAuth-клиентов MAS задаётся явно в `config.yaml`
  (`policy.data.client_registration`): только https и совпадение хоста
  `redirect_uri` с `client_uri`, контакт необязателен. Так внешние сервисы и
  Element X регистрируются сами, а обновление MAS не меняет правила молча.
- `health` показывает федерацию, MAS и готовность OAuth-входа для внешних
  сервисов (`auth_metadata` и регистрация клиентов), `info` — режим аутентификации.
- Документация: `docs/federation.md`, `docs/external-integration.md`.

### Изменено
- `manage.sh registration` и `password-reset` с MAS работают через него, а не
  через `homeserver.yaml` и `users.password_hash`.
- Бакет MinIO больше не получает анонимный доступ на скачивание: Synapse ходит с
  ключами, публичная политика раздавала бы вложения по прямой ссылке.
- Неудачный вход администратора на последнем шаге установки не роняет `start.sh`.
- `install.sh` ставит `python3`, если его нет.

### Исправлено
- В `homeserver.yaml` писалась опция `block_non_local_invites`, которой в Synapse
  нет: он молча игнорировал её, а администратор считал, что внешние приглашения
  заблокированы. Строка убрана; ограничение федерации обеспечивает whitelist.

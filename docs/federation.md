# Федерация: как связать два сервера

Федерация — это когда пользователи вашего сервера переписываются с пользователями
другого Matrix-сервера, а комнаты живут на обоих сразу. Для этого оба сервера должны
быть видны друг другу снаружи и разрешить друг друга в настройках.

## Что должно работать у вас

Инсталлятор настраивает всё это сам, проверить можно одной командой:

```bash
./manage.sh health
```

Строка «Федерация» должна быть зелёной. Что за ней стоит:

- `https://<домен>/.well-known/matrix/server` отдаёт `{"m.server": "<домен>:443"}` —
  так другие серверы узнают, куда вам стучаться. Порт `8448` тоже открыт и отвечает.
- `https://<домен>/_matrix/key/v2/server` отдаёт ключи подписи вашего сервера.
- Порты `80`, `443`, `8448` открыты в файрволе сервера **и** в панели провайдера
  (Security Groups у облаков — частая причина «у меня всё открыто, а не работает»).
- Сертификат валидный. Самоподписанные и просроченные федерация не принимает.

## Режимы

| Режим | Что значит | Когда брать |
|---|---|---|
| **whitelist** | общаемся только с перечисленными серверами | корпоративный сервер, есть партнёры — **по умолчанию** |
| **closed** | ни с кем | изолированный контур без внешних контактов |
| **open** | со всем Matrix-миром | публичное сообщество; для компании — нет |

Режим и список хранятся в `config/synapse/homeserver.yaml`
(`federation_domain_whitelist`). Synapse читает список **только при старте**, поэтому
все команды ниже перезапускают его сами — короткий разрыв соединений у клиентов при
этом нормален.

## Команды

```bash
./manage.sh federation --list                        # режим и список
./manage.sh federation --add chat.partner.ru         # добавить
./manage.sh federation --remove chat.partner.ru      # убрать
./manage.sh federation --mode whitelist|closed|open  # сменить режим
./manage.sh federation --test chat.partner.ru        # проверить связность
./manage.sh federation                               # интерактивное меню
```

`--add` в режиме `open` переводит сервер в `whitelist` — иначе добавление домена не
имело бы смысла. `--remove` последнего домена оставляет пустой список, то есть
**закрывает** федерацию: команда об этом предупредит.

### Список по ссылке

Если партнёр или сервис, к которому вы подключаетесь, публикует список своих серверов,
его можно забирать целиком:

```bash
./manage.sh federation --sync-from https://example.com/matrix/servers.json
```

Принимаются три формата: JSON-массив строк `["a.ru","b.ru"]`, объект
`{"domains": [...]}` и просто домены построчно. Текущий список **заменяется**
полученным; команда печатает, что добавила и что убрала, и не трогает файл, если
ответ пустой или содержит что-то, не похожее на домен. Для регулярного обновления
поставьте её в cron.

## Проверка связности

```bash
./manage.sh federation --test chat.partner.ru
```

Команда проходит по цепочке в обе стороны и говорит, где обрыв:

1. Есть ли партнёр в вашем whitelist (без этого его сообщения вы отбросите).
2. Что отдаёт `/.well-known/matrix/server` партнёра и куда реально идти.
3. Отвечает ли его `/_matrix/key/v2/server` и совпадает ли `server_name` с доменом.
4. Видны ли снаружи вы сами — тот же тест в свою сторону.

Одного зелёного теста мало: **партнёр должен добавить ваш домен у себя и прогнать тот же
тест**. Федерация симметрична, и настроить её односторонне нельзя.

## Ключ подписи

`config/synapse/<server_name>.signing.key` — то, чем ваш сервер подписывает всё, что
отправляет другим. Другие серверы запоминают публичную часть ключа за вашим доменом.
Если ключ потерян, они перестанут вам доверять, и восстановить это невозможно —
только новый домен и новые аккаунты.

```bash
./manage.sh backup-key --out ~/matrix-signing-key
```

Файл нужно унести с сервера: менеджер паролей, офлайн-носитель. Обычный бэкап
(`./manage.sh backup`) тоже его включает, но он делается по расписанию, а ключ нужен
с первой минуты.

## Что не делает whitelist

Whitelist — барьер транспортного уровня: с кем сервер вообще разговаривает. Он не решает,
кто из пользователей может писать кому, приглашать в комнаты или искать людей в каталоге —
это политики уровня комнат и пользователей, и они настраиваются отдельно (на стороне
Synapse — модулями, на стороне комнат — правами участников).
